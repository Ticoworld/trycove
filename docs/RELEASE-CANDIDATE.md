# Release candidate integration

The release candidate is based on `ec6a347443a6cc92d27116189955f3f78526ad19`, which already contains `main` at `9e8a21f668eea4836ba5c4bd602e8ec7d451e9c3`. No merge or production database write was performed.

A read-only PostgreSQL backup of the configured database was restored to an isolated PostgreSQL 18 instance. All 36 public tables matched the source by row count and row-content digest immediately after restore. The existing catalog importer then imported the 51 pinned qualified listings into the isolated copy. Replay was idempotent, an intentional conflicting fixture was rejected, and the 32 tables outside the catalog import matched the source afterward. Both previously published Owl Pilot and QuotaCell Trial Rooms and their retained sessions and feedback remain in the copy. The source contained the genuine Owl Pilot product and opportunity references. The pre-import source inspection found no existing IDs among the selected 51 projects, 51 source records, 40 repository records, or 78 category signals.

For an isolated integrated preview, `TRYCOVE_QUALIFIED_PREVIEW=1` and `TRYCOVE_INCLUDE_PUBLISHED_LEGACY=1` retain the reviewed historical catalog policy while allowing products from existing published Trial Rooms that are outside the reviewed catalog. Review-required and deferred catalog identities do not qualify through that exception. With the second flag unset, the previous strict preview behavior remains unchanged.

An additional disposable database copy was used to exercise an Owl Pilot session and explicit feedback report approval and Results listing. All four tasks were marked unattempted and the note identified the session as a test fixture. No report was published to the source or the integrated preview database.

GitHub sign-in, ownership management, trial editing, and authorized follow-up remain unverified in a staging environment: no staging Neon Auth endpoint, cookie secret, GitHub OAuth application configuration, or authorized builder session was available in the local preview. Provision those for an isolated staging origin and test with an authorized account. Before any future write to a serving database, independently verify its target identity, a restorable backup, the migration journal, and all catalog identity/provenance collisions. Do not use the isolated preview backup as a substitute for a fresh serving-database backup.
