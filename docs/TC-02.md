## Implemented path

- The Owl Pilot Passport and its source-backed `user-testing` Problem Map record link to the same four-task Room.
- The task definition is a reusable versioned data shape: product identity, live application identity, source request, safety boundaries and task observations are snapshotted when a session starts.
- A session uses a random non-secret URL id plus a separate 256-bit browser cookie. Only the SHA-256 digest of the cookie token is stored. The cookie is HttpOnly, SameSite=Strict, path-scoped to that one session and Secure in production. The local resume list stores only session ids; the cookie is still required to read a session.
- Task outcomes are `completed`, `failed`, `stuck` or `skipped`; optional notes are capped at 1,200 characters. Each save appends a step event and a content-hashed receipt version in one database transaction. Finishing appends a final version and makes the session read-only.
- Private sessions do not appear in the Integration Lab or public Results list. Their session and step data use separate tables and are available only through the matching session cookie. Receipts state that results are self-reported, identities are not collected, and human participation is not independently verified.
- The session token is hashed and page-level access is isolated, but note text is not encrypted per session at rest. The Trycove server/database operator can read stored notes; testers are told this before starting.
- Trycove does not ask for a seed phrase, private key, passkey, address or signature, and it never approves or submits an Owl Pilot transaction.
