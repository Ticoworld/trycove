# Stage 2 hosting and historical evidence

1. Provision a dedicated Trycove Supabase project. Disable the Data API. Runtime uses server-side Drizzle and the Supavisor transaction pooler on port 6543. Use the direct PostgreSQL connection or the session pooler on port 5432 for migrations. Store the database connection strings privately.
2. In GitHub, create an OAuth app with the Supabase provider callback URL shown in the Supabase GitHub provider settings. Enable GitHub in Supabase and supply the app client ID and secret there. Set the Supabase Auth Site URL to the production HTTPS origin and add exactly that origin plus /auth/callback to the redirect allowlist. For email OTP, configure and verify custom SMTP and use the Supabase email template containing the Token variable. Enable TRYCOVE_CUSTOM_SMTP_READY=true only after delivery is working.
3. Link Ticoworld/trycove in Vercel. Set TRYCOVE_PUBLIC_URL to the production origin, NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY to the Trycove project settings, and DATABASE_URL to the private transaction-pooler URI. Leave TRYCOVE_WRITE_KEY unset on the hosted app. To bootstrap an organizer, verify the intended authenticated user's UUID, set TRYCOVE_BOOTSTRAP_ORGANIZER_ID to that UUID, and have that account use the Account workspace bootstrap button. Confirm the audit entry and remove the bootstrap variable.
4. Before any production migration, stop local writers and preserve a consistent cold copy of the PGlite data directory. Verify that a disposable copy opens and that the evidence you intend to preserve is present. From the authorized tester browser, download the Owl Pilot approved JSON and save the exact bytes with its X-Content-SHA256 digest. Keep the backup, export and sidecar privately. Production migration and historical import are pending while these prerequisites are unresolved.
5. Apply pnpm migrate using TRYCOVE_MIGRATION_DATABASE_URL from the private migration connection. For an existing database with no migration journal, compare its catalog against the applicable original migration chain and resolve discrepancies before baselining. The migrator refuses an untracked schema.
6. Prepare a reviewed UTF-8 JSON manifest with version 1 and arrays named projects, sources, repositories, opportunities and evidence containing the corresponding Drizzle row shapes. Select explicit canonical Product Passport IDs including ckbuilder-owlpilot-67, preserve existing source IDs, links, revisions and observation timestamps, and review source payloads for public provenance. Record manifest and export SHA-256 values. The importer accepts up to 300 projects and 1,200 rows in each source array. Footprints, session credentials, private notes and follow-ups are outside this bundle. Run pnpm exec tsx scripts/import-public-history.ts with the manifest path and manifest digest. Run pnpm exec tsx scripts/import-approved-feedback.ts separately with the tester-approved export path and its digest when that export is available. Confirm the returned counts and digest. A repeated import checks the same rows and report bytes without duplicating them.
7. Deploy on Vercel and use independent browser sessions to verify public navigation, GitHub callback and logout, ownership, cross-project denial, anonymous enrollment, account linking, approved feedback, listing consent and revocation. Verify that records survive redeployment and that the Data API exposes no Trycove data.
