# Connection discovery investigation — 2026-11-16

## Documented need: DripFund × Cellora

- [CKBuilder issue 2](https://github.com/Nervos-Community-Catalyst/CKBuilder-projects/issues/2) explicitly asks how to design scalable indexing for many creators and donation cells. It reports a testnet MVP. This is the issue author's statement, not verified production behavior.
- [DripFund indexer at 34241019](https://github.com/adisuyash/ckb-notes/blob/34241019e35f4e4f00f505f5b6aac24619a1f400/buy-me-a-coffee/backend/services/indexer.ts) uses `ClientPublicTestnet`, converts the configured address to a lock, calls `findCellsByLock`, decodes output data and fetches transaction headers for timestamps. Its `@ckb-ccc/shell` dependency is specified as `*`, so a compatible version is not established.
- [Cellora cells route at a534c38f](https://github.com/Antismart/cellora/blob/a534c38f248c0406eeafee94adadb8c2c9072f8a/crates/api/src/routes/cells.rs) exposes `GET /v1/cells` by lock hash, optional `include_data`, `is_live` and a cursor. Data is off by default and omission of `is_live` includes live and consumed cells. Its [issue 12](https://github.com/Nervos-Community-Catalyst/CKBuilder-projects/issues/12) reports a dev-chain deployment and testnet as a future milestone; its earlier feature list distinguishes current functionality from planned APIs. The pinned source demonstrates a route exists, not that a compatible testnet service is deployed.
- `pnpm investigate` clones the saved source revisions and checks these interface markers. This is a reproducible **source-level check**, not execution of the two applications together. No lock-hash conversion, cursor behavior, timestamp mapping, network compatibility, signing, chain state or live integration has been verified. An integration needs a response adapter, explicit data and liveness parameters, an indexing/ordering comparison and a testnet-backed provider. The query path is read-only; authentication and rate limits still require review. Cellora's repository declares FSL-1.1-ALv2; this investigation reads source and does not copy its implementation.

## Other surfaced candidates

- **pckt × Cellora:** pckt's [transaction code](https://github.com/RobaireTH/pckt/blob/f351c6c2eea531814e78d557b8a23c2695df292d/frontend/src/tx.ts) uses `findCellsByLock` and parses `outputData` to locate a live packet cell. A Cellora adapter would need explicit live filtering, fresh chain state and exact packet decoding. The issue's separate request for *multi-code-hash indexing* is not equivalent to Cellora's lock-hash query; it was removed as a documented-need match. This is an architectural hypothesis, not a verified solution to that request.
- **pckt × CellFlow:** the same pckt file signs and sends through `relayTransaction`, while [CellFlow's CCC adapter](https://github.com/tydeptrai21042004/CellFlow/blob/027ce1c4202a3e62ae504bc9aa0f14169b2ca085/packages/ccc/src/ccc.ts) signs in `prepareTrackedTransaction` and broadcasts with `signer.client.sendTransaction`. `pnpm investigate:relays` checks the pinned source markers. These interfaces are not drop-in equivalents; duplicate signing/broadcast and relay semantics need investigation. No runtime recovery or adoption is claimed.
